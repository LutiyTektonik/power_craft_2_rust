# Опубликованная версия и границы точного переноса

Проверка выполнена 14 ноября 2026 года. [Страница PowerCraft 2](https://www.curseforge.com/minecraft/mc-mods/powercraft-2) помечает Logic/Storage/Mobile как находящиеся в разработке. [Последний опубликованный beta-файл](https://www.curseforge.com/minecraft/mc-mods/powercraft-2/files/3030146) — powercraft-0.1.0B.jar, 12 августа 2020 года, Minecraft 1.7.10. Это загрузчик; модули распространялись отдельно через официальный PowerCraft/Maven.

Из [закреплённого Maven-дерева](https://github.com/PowerCraft/Maven/tree/2fce13e3dccd0ec0a9db7dd19416d308509bfa1c) получены **26 архивов** — 13 runtime-JAR и 13 source-JAR. Все размеры и Git blob ID совпали с удалёнными метаданными, CRC прошли; class-файлы проверены по заголовку. **Ни один JAR не запускался.** Архивы и оригинальная графика не входят в Git/моды/передаваемый набор.

Полные hashes и классы — `PUBLISHED_FILES.json`/`PUBLISHED_AUDIT.json`; реестр source-JAR — `PUBLISHED_MECHANICS.json`. Он содержит 427 Java-файлов, 62 декларации объектов, 148 деклараций рецептов с учётом циклов/режимов и 78 GUI/container/виджет-классов. Это число текстовых деклараций, не число разных рецептов, одновременно доступных игроку. Сложные/3D-обработчики отмечены для ручной проверки.

## Сравнение с GitHub-исходниками

Из 427 Java-файлов **404 совпадают побайтно** с исследованным commit PowerCraft/2.0. Различаются 23 файла, главным образом App/загрузчик и настройка рецептов, а также crafting-tool/дымoход. В частности, опубликованные PCtr_BeltHelper, PCtr_BlockBeltNormal, PCtr_BlockBeltSpeedy и PCtr_BlockBeltBreak соответствуют изученному поведению. Нельзя автоматически приписывать beta-релизу позднейшие medium/legacy-настройки GitHub.

## Подтверждённое основание следующей механики

Опубликованный Normal вызывает storeNearby(..., false), Brake — storeNearby(..., isPowered). После достижения половины блока первым выбирается контейнер по движению, затем поперечные соседи в порядке north/east/south/west, затем сверху. Запитанный Brake игнорирует границу половины. После частичного принятия проверяются следующие цели; после полного принятия сущность удаляется.

Опубликованный Speedy **не вызывает storeNearby**. Поэтому в 0.3.0 его поведение не расширено; быструю линию перед сундуком следует завершить обычной лентой. Это осознанное соответствие опубликованному коду, не потеря уже существовавшей функции.

Первый срез Horizon охватывает chest/trapped_chest/furnace/hopper/dispenser/dropper/brewing_stand через официальные slot/face-правила. Вагонетки и mod-контейнеры пока не перенесены. Не включаются специальные действия ведра/бутылки, despawn-изменения или новые игровые объекты.

## Политика очереди

Рабочий объём сейчас — существующие основные механики Transport, затем подтверждённый Core/Deco/Net/Light/Hologram/Teleport/Machines по зависимостям. Logic/Storage/Mobile, неисправные legacy-рецепты и закомментированные TODO-подфункции **отложены**, их не исправляют/не портируют в рамках текущей очереди. Планы Weasel/энергетики и удалённый CheckPoints не реализуются.

Сравнение всех зарегистрированных элементов и собственных адаптаций находится в `PORTING_COMPARISON.json`; текущие статусы — `PORTING_PROGRESS.md`. Публикация и исходник — более сильное основание, чем название класса, но не заменяют запуск оригинала: там, где нет игрового подтверждения, это прямо отмечено.

## Повторение анализа

`python3 scripts/audit-published.py --published /путь/к/дереву/Maven --source /путь/к/исходникам/2.0` проверяет hashes и повторяет индексы. `--source` необязателен для аудита архивов, но нужен для сравнения с GitHub. Внешние JAR нужно получать из официального Maven по указанным Git blob ID; не запускать их в Horizon и не включать в релиз.
