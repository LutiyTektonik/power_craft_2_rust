# Архитектура

Одна Cargo-библиотека содержит независимую механику Transport. Core, Logic, Storage и Mobile остаются логическими областями будущей работы. Пустые пакеты для них не созданы. Циклических Cargo-зависимостей нет; игровых зависимостей в библиотеке нет вообще.

## Поток данных

1. Контентный загрузчик Horizon регистрирует `powercraft2:conveyor` из JSON, включая предмет блока, модель, форму, четыре состояния, рецепт и творческую вкладку.
2. Именованный `state_for_placement` выбирает `facing` по `PlacementContext.yaw`, только для нашего блока и если предыдущий обработчик не ответил.
3. `entity_tick_listened` включает штатную доставку серверных событий тика, когда мод включён.
4. `entity_tick_post` сразу отбрасывает не-предметы и выключенный мод. Через typed `Host` он читает временный `EntityRef`, позицию, опорный блок, направление, скорость и признак земли.
5. `velocity_for_tick` проверяет координаты, поверхность и входные числа, задаёт ограниченную горизонтальную скорость и центрирование, сохраняя вертикальную компоненту. Адаптер проверяет загруженность следующей позиции и передаёт скорость штатному `EntityRef::set_velocity`.

Функции ядра реально написаны. Компиляция адаптеров и этот поток внутри игры пока не проверены.

## Тики и физика

Единица скорости — блоки за игровой тик. Номинальная заданная скорость 0,1; центрирование ограничено 0,04 блока за тик. После события Post эта скорость используется последующей штатной физикой. Итоговую скорость с учётом коллизий и трения надо измерить в игре; число 0,1 не является проверенной фактической скоростью перемещения.

Это осознанно упрощённый перенос. Java-оригинал имеет ускорение 0,14, верхний горизонтальный ориентир 0,5, специальные правила хранения, упаковки и удержания предметов. В прототипе горизонтальная скорость задаётся ограниченно без накопления; перенос упаковки, инвентарей, подъёмников и предотвращения despawn не выполнен. Игроки и мобы не двигаются нашим кодом.

Нет собственного цикла тиков, фонового потока или зависимости от кадров. Отмена Pre другим модом препятствует Post по контракту Horizon. Исчезнувшая при слиянии сущность даёт `None` и пропускается. Обработчик ничего не создаёт и не удаляет, не меняет стеки, не продлевает срок жизни предмета.

## Состояние и сериализация

Долговременное состояние конвейера — имя блока и `facing=north|east|south|west`. Его записывает обычное сохранение блоков Horizon. Свойство по умолчанию — `north`. Высота поверхности 0,25 одинакова в модели, outline, collision и ядре; аудит проверяет соответствие JSON. Независимые Rust-тесты проверяют строковый round trip направления; настоящая запись/чтение чанка ещё не проверена.

Скорость и положение предметов сохраняются движком как состояние обычных item entities. Не создаются отдельные block entities, глобальный список лент, файлы на каждый механизм или собственные пакеты синхронизации. Выгрузка чанка не оставляет объектов в состоянии мода. Перед выходом в незагруженный блок адаптер обнуляет горизонтальную скорость; это не заменяет политику entity-ticking chunks движка и требует игровой проверки.

Неизвестный `facing`, отсутствующий блок, нечисловые координаты и устаревшие handles приводят к отказу от изменения. Мигратора сохранений Forge 1.7.10 нет. Новые типы механизмов со своим состоянием должны получить версионированные схемы и явную миграцию, предпочтительно на штатных block entities/attachments.

## Границы интеграции

Контент — `content/`. Адаптеры — маленькие Rust helper-файлы. Конфигурация — проверяемый тип `Config`, пока с фиксированными значениями; пользовательского меню конфигурации нет. Регистрация — только декларации контента. Сериализация направления принадлежит движку; `Direction` знает только допустимые строковые значения.

Все Rust-функции независимого ядра используются из одного исходника и в Cargo, и в модуле Mixins. Нет копирования с генерацией второго Rust-файла. Typed API вызывается из официальных HEAD-хуков; отдельный `[api]` trait-пакет не добавлен, поскольку этот путь обозначен draft и усложняет зависимости для первого среза.

Само ядро имеет постоянную стоимость и не выделяет память при расчёте движения. Нельзя приписывать это всему адаптеру: методы typed API делают поиски сущностей, некоторые линейные, и возвращают строки блоков. Доставка entity tick также затрагивает штатные списки других семейств. Профилирование большого количества предметов и подбор более узкого официального API — обязательный этап перед массовым использованием.
