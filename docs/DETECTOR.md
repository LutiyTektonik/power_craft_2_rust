# Детекторная лента 0.4.0

Новый ID: `powercraft2:detector_conveyor`. Предмет, четыре facing, две визуальные стадии powered, loot и два рецепта зарегистрированы в собственном namespace. Форма высотой 0,25 и расчёт движения такие же, как у принятой normal-ленты. Исходная детекторная лента опубликованного PowerCraft 2 имеет сигнал 15 и опрос сущностей в кубе блока; упаковка и despawn-подправила оригинала пока не перенесены.

## Сигнал и сущности

На каждом серверном игровом тике определяется пересечение реальных AABB сущностей с кубом [x,y,z]..[x+1,y+1,z+1]. Сигнал 15 сохраняется, пока есть хотя бы одна подходящая сущность, затем становится 0. Клиент читает стандартное свойство powered; зелёные полосы показывают состояние. Кадры рендера не управляют логикой.

Используется публичный `LevelAccess::count_entities_at` и `EntityQuery::Everything`: те же фильтры блоковых триггеров, что у Horizon. Учитываются предметы, мобы, обычные игроки и LAN-гости; spectator/игнорирующие триггеры сущности отсекаются двигателем. Существующая отмена `player_physical_trigger` другим модом учитывается. Это современная адаптация фильтра триггеров, не полное воспроизведение всех Forge-исключений sneak/sticky boots (ботинки ещё не перенесены).

Публичный Host::entities_in здесь не использован: в закреплённом исходнике он отбирает центры, а не пересечения AABB и помечен для редких запросов. Query получает GameLevel через уже существующий `Game::with_level` — минимальный **читающий внутренний мост к конкретному SHA**. Он не редактирует функции движка, не записывает сущности и не создаёт свой spatial index. Проверять мост при любом обновлении Horizon; строгий pin архива обязателен.

## Реальные хуки

- block_entity: создаёт только наш тип `powercraft2:detector_conveyor`, только если другой обработчик ещё не дал сущность.
- block_entity_ticks: включает тик только нашего блока и не сбрасывает ответы других модов.
- block_entity_tick: опрашивает сущности на сервере, обновляет только собственный powered через официальный set_block_property_with flags=2.
- block_signal: возвращает 0/15 из переданного state, для strong и weak на всех гранях, без чтения/изменения мира внутри redstone-рекурсии.
- is_signal_source: объявляет источник только для нашего блока, чтобы провода соединялись с ним.

Все хуки именованные, версия 1, HEAD, без OVERWRITE/отмены чужой логики. Минимальный API 381 уже покрывает их; Horizon и Mixins не обновлялись.

update_signal_neighbors вызывается только при изменении powered и один раз при первом тике после загрузки. Щелчок `minecraft:block.lever.click` (ссылка на штатный ресурс пользователя, не скопированный звук) играет только на переходах, volume 0,15/pitch 0,5. Это современное отображение исходного random.click. Если сервер выключил мод через native_on, powered очищается на следующем тике; опрос сущностей выключенного мода не выполняется. Объявление источника/создание block entity структурны и сохраняются для целостности мира.

## Сохранение и выгрузка

Долгосрочное состояние — обычные facing и powered в block state Horizon. Block entity не имеет собственного инвентаря или пользовательских NBT-полей. Одно значение в её публичном `data` служит только runtime-флагом первой отправки соседям: по контракту ModBlockEntity это поле **не сохраняется**. После каждого восстановления из чанка первый тик перепроверяет занятость и уведомляет сеть, даже если сохранённый powered уже верен. Поэтому оставшееся от сохранения true не защёлкивает сигнал навсегда.

Тик привязан к штатному жизненному циклу block entity: только загруженные/симулируемые чанки; после разрушения или замены удаляется движком. Глобального реестра детекторов, сохранённых runtime-ID и фонового потока нет.

Данный первый срез использует штатную block entity. Horizon не перемещает такие блоки поршнями; соответствие поршневому поведению оригинала пока не восстановлено. Тик mod block entity в этом SHA также помечает чанк dirty, даже если данные не менялись. Опрос каждой загруженной ленты каждый тик имеет стоимость: мост создаёт штатный level-view, запрос проходит по сущностям. Реальная нагрузка/массовые линии пока не профилированы; не объявлять нулевые аллокации или O(1) всему адаптеру. При необходимости оптимизировать через узкий официальный query/lifecycle API, не глобальный перехват рендера/физики.

## Движение, разгрузка и рецепты

Предметы движутся с прежними 0,1 блока/тик, Y/коллизии/pickup принадлежат Horizon. Игроки и мобы только обнаруживаются; движение ими не управляется. Detector, как опубликованный класс, сам не выгружает в контейнер: ставьте после него normal/brake/Speedy для выгрузки. Разрешение разгружать Speedy — отдельное прямое указание пользователя, оно сохранено в 0.4.0.

Рецепты из beta-релиза: вертикально pressure plate → normal conveyor → redstone, выход 1. Разрешены stone_pressure_plate и oak_pressure_plate (современное имя старой wooden_pressure_plate). Старые рецепты трёх лент не менялись. В творческую вкладку добавлен один элемент, в реальные ru_ru/en_us — по одному имени; прежние ключи/порядок старых элементов сохраняются.

## Что подтверждено

45 Rust- и 28 Python-тестов прошли, официальный native.py check с настоящим Horizon и валидатор архивов прошли. Это компиляция/модельные/структурные проверки. Движение, работа настоящих проводов/ламп, reload, сигналы у игроков и LAN **ещё требуют запуска 0.4.0 в игре**. Детальный список — TESTING.md.
