# Облачная среда

На старте: Debian GNU/Linux 13.6 (trixie), архитектура инструментов x86-64, 3 доступных CPU, RAM около 9,7 ГиБ, swap отсутствует. В `/workspace` около 7,5 ГиБ свободного места из 7,9 ГиБ. Это наблюдение начала сессии, а не гарантированные ресурсы следующего запуска.

Доступны Git, Python 3.12.14, GCC/cc 14.2, GNU ld/ar и make, curl, ripgrep и gh. Rust/Cargo/rustfmt/Clippy, rsync и отдельный Horizon CLI не обнаружены. Системный помощник `/usr/local/bin/cloud-agent-packages` отсутствует. Пользователь `agent`, uid 1000; системная установка не выполнялась.

Создан отдельный записываемый Git-репозиторий `/workspace/powercraft2-horizon`, ветка `work/transport-prototype`. Служебный `/workspace/.git` пустой и доступен только для чтения; он не использовался. `origin` не настроен. GitHub-коннектор позволил прочитать официальные публичные исходники, но список доступных пользовательских репозиториев вернул пустой результат. Права push на Horizon отсутствуют. Отправка на GitHub и PR не выполнялись.

## Сетевая проблема

Обычные `git ls-remote` и `curl` завершились ошибкой подключения к настроенному прокси `proxy:8080`. Проверялись `github.com`, `static.rust-lang.org`, затем официальный установщик `sh.rustup.rs` через bootstrap. Ответа целевого сервиса не получено; **блокировка домена не установлена**. Причина на наблюдаемом уровне — недоступный прокси. Прокси, CA и TLS не изменялись. Попытки дополнительного сетевого доступа были прерваны и не подтвердили работоспособность.

Коннектор GitHub и веб-инструмент имели отдельный рабочий путь чтения, поэтому исследование исходников удалось. Это не восстановило shell-доступ для скачивания Rust и Cargo dependencies. Официальный `native.py check` при попытке загрузить `codeload.github.com` дополнительно получил `PermissionError: Operation not permitted` на создании сетевого сокета — ограничение песочницы, не ответ домена. Повторный обход сетевых ограничений не предпринимался.

## Воспроизводимость и ресурсы

`scripts/bootstrap.sh --install` загружает только официальный rustup, устанавливает minimal stable 1.95.0 с rustfmt и Clippy в `.tools/`, без изменения HOME или системных прав. Horizon CLI устанавливается с точным `--rev`. В этой сессии команда остановилась на скачивании rustup, код возврата 7; установленного Rust после неё нет.

Обычная разработка: максимум два Cargo jobs, отключён incremental, уменьшен debug. Нет сторонних crate-зависимостей у нашего ядра. Rustup/Cargo, tool-build cache, `target/`, native staged sources и `dist/` исключены из Git; временный cache сборки Horizon CLI удаляется после успешной установки. Перед тяжёлым запуском проверяются как минимум 6 ГиБ свободного диска; это начальный порог, а не гарантия размера сборки. Полный движок не скачивался: исследовательские файлы вне репозитория занимают несколько мегабайт. Тяжёлая интеграция запускается отдельно и один раз после устранения блокера; базовый CI не собирает всю игру.

Для восстановления продолжения нужен работоспособный сетевой путь Cloud к `sh.rustup.rs`, `static.rust-lang.org`, GitHub/codeload и реестру crates.io с его CDN; нельзя утверждать, что эти домены сейчас запрещены. После восстановления запустить bootstrap и обычный check, затем интеграцию. Ничего устанавливать на локальную машину пользователя для этих этапов не требуется.
