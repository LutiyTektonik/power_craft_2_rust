# Фактический статус

Состояние на 14 ноября 2026 года: **исходный прототип, не проверенный в игре и не скомпилированный в этой среде**. Сетевая песочница препятствует скачиванию компилятора и полного движка. Продолжение не требует менять архитектуру или устанавливать что-либо на локальный компьютер пользователя.

## Создано

- Git-репозиторий и рабочая ветка, согласованные точные upstream SHA, компактная Cargo-библиотека без сторонних crate-зависимостей.
- Настоящие Rust-функции направления, проверки координат, ограничения скорости и центрирования предметов; 11 содержательных модульных тестов.
- Три адаптера именованных официальных hooks: слушатель, серверный item Post, направление размещения. Методы существуют в прочитанных исходниках; проверки типов компилятором ещё нет.
- Декларация отдельного блока `powercraft2:conveyor`, предмет, четыре состояния, формы высотой ¼ блока, модель, рецепт, creative tab, русский/английский перевод и две оригинальные PNG-текстуры.
- Скрипты bootstrap/check/build, загрузка точных официальных native-инструментов в локальный игнорируемый каталог, проверка происхождения и структуры, 13 Python-тестов, базовый CI и отдельная ручная тяжёлая проверка.
- Исследование всех исходных модульных областей, инвентаризация 427 Java-файлов и документация лицензий/ограничений.

Известных ошибок этих структурных проверок сейчас нет; это не исключает ошибок Rust или интеграции.

## Ревизия для Windows 11

Работа сохранена в отдельной ветке `work/windows11-review`. [Аудит функций](FEATURE_AUDIT.md) различает независимое Rust-ядро, декларации контента и реальный код адаптеров, который пока не был применён/скомпилирован. [Инструкция](WINDOWS11.md) основана на исходниках Launcher, содержит строгий вход `native-pinned/`, команды и восемь игровых сценариев. [Машиночитаемый отчёт](WINDOWS11_VERIFICATION.json) фиксирует успешные и заблокированные команды.

Повторный официальный `native.py check` остановился на той же сетевой ошибке до Mixins/Cargo. Официальная упаковка `.hnmod` выполнена успешно. Создан экспериментальный `dist/powercraft2-windows11-test-kit.zip`; он не считается установочным релизом, прошедшим официальный валидатор. Нативная часть упакована официальным инструментом; контентная пока только собственным скриптом. Сборочные сценарии исправлены, чтобы при наличии Cargo проверялся именно результат официального content build и не использовался старый native-архив из кэша.

GitHub по-прежнему недоступен для сохранения этого проекта: `origin` отсутствует, коннектор вернул пустые списки доступных репозиториев. Запрошен URL репозитория назначения. Никакие чужие ветки не менялись; push и PR не выполнялись.

## Сборочные файлы

`dist/powercraft2-0.1.0-content.hmod` — контентный ZIP, упакованный по документированному формату нашим скриптом. `dist/powercraft2-0.1.0.hnmod` — bundle Rust-исходников, упакованный официальным инструментом. Они доступны как результат работы, но не объявляются проверенными устанавливаемыми релизами. В Git эти производные файлы не добавляются.

Для полноценной приёмки сначала выполнить `scripts/check.sh` и `scripts/check.sh --horizon`. Наличие успешного CI пока не подтверждено: GitHub-репозиторий назначения не подключён, workflow не запускался на GitHub. Изменения сохранены локальными коммитами; push и Pull Request не выполнены.

## Проверка в Minecraft после устранения блокеров

1. Создать отдельный тестовый каталог/мир с ресурсами Minecraft 26.3. Собрать pinned native-клиент, включить контентный `.hmod`, перезапустить игру после регистрации блока.
2. Получить блок через вкладку, рецепт и `/give`; проверить соответствие модели коллизии, выпадение блока при разрушении и размещение по всем четырём направлениям взгляда.
3. Бросить предметы на прямую линию и поворот. Проверить правильную ось, движение через x/z=16 и отрицательные координаты, стоп у незагруженного чанка, падение в конце и коллизию со стеной. Проверить, что соседние обычные блоки и летящие предметы не приводятся в движение.
4. Сравнить при низком/высоком FPS, `/tick freeze` и возобновлении тиков. Измерить фактическую скорость с учётом vanilla-физики; сейчас она не измерялась.
5. Сохранить/закрыть/открыть мир, выгрузить/загрузить чанки: направление, число и содержимое item stacks должны сохраниться. Проверить удаление/слияние предмета и отсутствие возобновления работы по устаревшему handle.
6. На LAN/сервере с двумя игроками проверить одинаковое положение/скорость, отсутствие дюпов при pickup и выгрузке, одинаковую регистрацию контента. Затем совместную сборку с независимым модом, использующим другие namespaces.
7. Измерить серверное время тика на большой линии и большом количестве предметов. Не объявлять производительность достаточной по одному тесту ядра.
