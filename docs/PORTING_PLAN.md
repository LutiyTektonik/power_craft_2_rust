# План переноса PowerCraft 2

Источник: `PowerCraft/2.0` commit `795369c5a03c7cf39307398a432a5d644698e1df`. Проверены полное дерево, `settings.gradle`, все модульные `build.gradle`, все имеющиеся `*_App.java`, базовый/обычный конвейер, BeltHelper, базовое сохранение TileEntity и WorldData. Это инвентаризация и выборочный анализ поведения, не построчный аудит всех 427 Java-файлов. Полный список классов — `POWERCRAFT_INVENTORY.json`.

## Оригинальная архитектура

`powercraft/` — Forge-мод/загрузчик и менеджер модулей. `api/` — общий слой аннотаций, реестров, GUI GRES, инвентарей, пакетов, TileEntity и сохранения. `PC_Module`, `PC_FieldObject` и методы инициализации описывают регистрацию; `PC_BlockRegistry`, `PC_ItemRegistry`, `PC_RecipeRegistry` и другие реестры её выполняют. Модули используют Minecraft Entity/World/Block/Item и Forge GameRegistry.

Исходная сборка: Java 8, Minecraft `1.7.10-10.13.4.1558-1.7.10`, ForgeGradle `com.anatawa12.forge:ForgeGradle:1.2-1.0.+`. Загрузчик декларирует `FMLCorePlugin=powercraft.api.hooks.PC_Hooks`. Воспроизводить старую сборку с плавающим ForgeGradle или запускать этот plugin в Horizon не требуется.

Все 11 подключённых игровых модулей зависят от `api` и `powercraft`, а через них от Forge/Minecraft. Logic и Machines берут API через локальный dev-artifact/flatDir, остальные — project dependency. Есть обращения к объектам Core по имени, например PowerCrystal в рецепте Teleport; такие зависимости следует заменить общими внутренними декларациями или независимыми рецептами. Индустриальные сторонние моды не являются обязательной зависимостью проверенных модулей.

`PC_TileEntity` сериализует аннотированные поля в NBT compound `map` и синхронизирует данные через Forge TileEntity packets; `PC_WorldData` использует WorldSavedData. Эти форматы не переносить слепо. Новые состояния должны сохраняться средствами Horizon с версиями схем. Старые ID, metadata и NBT не считаются автоматически совместимыми.

Сложность относительная: малая — декларативный контент, средняя — несколько серверных механик, высокая — состояние/меню/мультиплеер, очень высокая — собственные сущности или сложный рендер. Оценки не являются обещанием сроков. Общая зависимость API + loader + Forge указана выше и относится к каждой строке.

## Последовательность

1. Восстановить разрешённый доступ Cloud к сети, установить закреплённый Rust, выполнить fmt/Clippy и все 11 Rust-тестов, исправить обнаруженные ошибки.
2. Применить bundle настоящим Mixins, выполнить официальный `native.py check powercraft2` и `cargo horizon-mod check` для обеих частей. Разобрать ошибки типов/видимости без выдуманных API.
3. Запустить с отдельным тестовым миром, проверить получение/размещение, оси, линию/поворот, предмет у края, тик-паузу, выгрузку и сохранение. Проверить LAN/сервер с двумя игроками, одинаковыми файлами и независимым простым модом.
4. Снять tick-time при большом количестве лент/предметов; решить проблему линейных поисков typed helpers, если она материальна, через официальный API или отдельный upstream запрос.
5. Завершить базовый Transport: правила конечной точки и выдачи в инвентарь, затем сортирующая/детекторная лента. Не переходить к большим модулям до принятия базового среза.
6. После Transport: простая часть Core/Deco, затем Logic и Storage, отдельными изменениями. Mobile, Teleport, Machines и сложный рендер — самостоятельные этапы с сохранением и мультиплеером.

Базовая лента 0.1.1 подтверждена пользователем, официальные компиляционные/форматные проверки выполнены; добавлены быстрая и тормозная ленты 0.2.0. LAN/профилирование и полная игровая приёмка ещё не завершены. Текущий порядок и статусы — в PORTING_PROGRESS.md.
