# Совместимость

Целевая исходная ревизия Horizon: `9f42064c11efe7ef3e5ed2baad7ddc2a3b36eea0`, Minecraft 26.3. Horizon Mixins: `e59da9094f0c2fdda6c627fe9eff22dec6a906f0`. Официальный cargo check с модом на этой ревизии прошёл. Исходный конвейер подтверждён пользователем в игре; плавность 0.1.1 также подтверждена пользователем. Три ленты 0.2.0 подтверждены пользователем; новая передача 0.3.0 требует игровой приёмки.

Обязательных сторонних модов нет. ID мода — `powercraft2`, все новые игровые данные — `powercraft2:*`, единственный добавляемый Rust-модуль — `powercraft2_transport`. В чужие каталоги и пространства имён мод не пишет.

## Использованные точки расширения

| Именованный хук, версия | Действие |
| --- | --- |
| `entity_tick_listened`, 1 | Устанавливает `listened=true`, если мод включён; не сбрасывает ответ других модов |
| `tick`, 1 | Только клиентская копия: предсказание той же скорости после штатной физики |
| `entity_tick_post`, 1 | Только `minecraft:item` над собственным конвейером; меняет скорость через typed API |
| `state_for_placement`, 1 | Только собственные ленты; выбирает направление, сохраняя уже данный ответ |

Хуки — HEAD без отмены и OVERWRITE. Каталог и blob-идентичность исходников записаны в `API_EVIDENCE.json`. Требуемый уровень хуков 381 покрывает чтение уровня; в выбранном движке имеется 415. Это не обещание поддержки любой ревизии с номером ≥381: добавляемый модуль и сборочный инструментарий привязаны к исходной структуре выбранного commit.

Используются `Host::on/entity/level`, методы `EntityRef::position/velocity/on_ground/set_velocity`, методы `LevelRef::block/block_property/is_loaded`, документированные `GameLevel::native_state_block/native_state_with_property`. Нет ручного редактирования функций движка. Официальный Mixins создаёт отдельное staged-дерево; исходный Horizon не меняется.

Для 0.4.0 также применяются block_entity, block_entity_ticks, block_entity_tick, block_signal и is_signal_source, версия 1; подробности в разделе 0.4.0 ниже.

## Возможные конфликты

- Несколько native-модов одной сборки должны согласовать ревизии движка и Mixins; полная совместная сборка здесь не выполнена.
- Поле `hooks` в официально упакованном `.hnmod` позволяет Launcher выбрать подходящую другую ревизию Horizon. Для строгого теста указанного commit используйте подготовленный `native-pinned/` без этого необязательного поля и проверяйте оба SHA в `native-mods.json`. Это сохраняет pin Mixins, который теряется при передаче одного внутреннего каталога bundle. См. `WINDOWS11.md`.
- Другой мод, меняющий скорость того же предмета на той же ленте, может переопределить результат. Нет эксклюзивной блокировки физики. Порядок HEAD задаёт Mixins: priority по убыванию, ID мода и ID инъекции по возрастанию; trait-обработчики идут после mixin-инъекций.
- Мод, отменивший Pre тика сущности, предотвращает наш Post. Это поведение сохраняется.
- Мод, претендующий на `powercraft2`, конфликтует по пространству имён. Другие разработчики должны использовать свои идентификаторы.
- Ресурс-пак может заменить нашу графику; это не должно менять игровую механику.
- Нативная часть не меняет размещение чужих блоков. Ориентация своего блока остаётся структурным правилом размещения даже при выключенном движении: `GameLevel` не предоставляет настройку `Host::on` этому адаптеру.

## Мультиплеер и данные

Контентный manifest явно имеет `side="both"`. Клиент и сервер должны иметь одинаковую контентную версию и одинаковое поведение нативной части. Horizon сверяет контентные моды при подключении; по документации native-моды пока не входят в такую сверку. Поэтому одинаковый набор нативных компонентов необходимо обеспечить на уровне сборки.

Движение выполняет авторитетный сервер; клиент получает обычные обновления item entity и с 0.1.1 предсказывает ту же силу ленты на своих копиях предметов. Нет собственного сетевого протокола, копирования стеков или обязательного мода-посредника. Серверная и LAN-проверки с двумя клиентами не проведены.

Единственное новое сохраняемое состояние — блок с `facing`. Не удалять определения этого блока из мира без резервной копии. Совместимость миров 1.7.10 с новым namespace не реализована. Будущие интеграции с инвентарями, энергией и защитой территории оформлять отдельными адаптерами с необязательными зависимостями и документированным поведением.

## Особенность исправления 0.1.1

Публичный setter скорости запрещает клиентские записи. Поэтому клиентский адаптер внутри официального tick-хука читает текущие world/registry и меняет только `Game::dropped` → `ItemEntity::velocity`. Это минимальная зависимость от внутренних полей выбранного commit, необходимая для правильного предсказания; ни position, ни previous, ни счётчики предмета не меняются. Функции движка не переписываются, render hooks и собственные пакеты не добавляются. Проверять эту связь при любом обновлении Horizon. В распространяемом `.hnmod` удалено необязательное поле `hooks`, поэтому его Horizon SHA является строгим pin. Локальный compatibility.json по-прежнему содержит минимальный уровень API 381 для официального инструментария.

## Изменения 0.2.0

Нативная и контентная части — обе **0.2.0**. Добавлены только `powercraft2:speedy_conveyor` и `powercraft2:brake_conveyor`. Старые ID/facing и восемь normal-файлов сохранены; новые блоки используют обычные состояния Horizon. В новой тормозной ленте собственный boolean powered — серверный кэш питания, не redstone-выход. Он перечитывается при обработке предмета, в том числе после загрузки чанка.

Дополнительные публичные helpers: Host::neighbor_signal (API 96) и Host::set_block_property_with (API 33). Уровень 381 менять не требуется. Пишется только собственный brake powered с UPDATE_CLIENTS=2, по изменению значения. Другие свойства/facing и чужие блоки не перезаписываются, соседние обновления не вызываются. Новых хуков и OVERWRITE нет. На пустой ленте cached powered/картинка могут обновиться лишь при следующем предмете; реальное питание на сервере не берётся из кэша.

В 0.2.0 обновить обе части на клиенте/сервере и выполнить native rebuild. Для возврата к 0.1.1 использовать резервную копию мира до установки новых блоков: старый content не знает новые ID. Совместная сборка с другими native-модами и LAN ещё не проверены.

## Изменения 0.3.0

Native/content обе 0.3.0, пины прежние. Все 29 definitions/assets/recipes из 0.2.0 сохранены, миграция/новые ID/блоки/хуки отсутствуют. Новое серверное взаимодействие вызывает публичные item_entities/set_item_entity (API 42) и insert_item (API 20), минимальный 381 уже достаточен. Чужие block states не переписываются; меняются только содержимое явно выбранного vanilla-контейнера и количество исходного предмета через штатные API.

Семь разрешённых типов перечислены в STORAGE_TRANSFER.md. Произвольные mod-контейнеры, composter/jukebox/shelf и вагонетки пока исключены; нет обещания универсальной атомарности для любых callbacks. Не расширять supports_storage без повторного анализа engine-контракта. Существующие native_container_accepts/slot rules не переопределяются. insert_item — native API авто-выхода, не событие движения обычного hopper; отмена inventory_move_item другого hopper-мода сама по себе не является отменой этой отдельной машины.

Политика отмены entity Pre/выключения нашего мода сохранена. Полное принятие выполняет обычное удаление item entity, не скрывает чужие события. Нового сетевого протокола нет; клиентское предсказание движения не пишет стеки. На обеих сторонах обновить версии и пересобрать native; LAN/совместная сборка пока не приняты. Порядок тика/сохранение и отсутствие дюпов проверяются в игре отдельно от компиляции.

## Изменения 0.4.0

Добавлен только powercraft2:detector_conveyor и одноимённый тип block entity; старые ID и состояния не переиспользуются. Дополнены creative tab/lang, прежние записи/рецепты/ресурсы сохранены. Native/content обе 0.4.0, нужен rebuild на обеих сторонах. Возврат к старому content из мира с новым блоком возможен только с подходящей резервной копией.

К прежним четырём хукам добавлены block_entity, block_entity_ticks, block_entity_tick, block_signal, is_signal_source (все v1 HEAD). Фабрика не заменяет чужой уже данный ответ, ticker/source не сбрасывают чужие флаги; сигнал читается из собственного state без world I/O. При изменении/первой загрузке собственный powered уведомляет соседей через штатный update_signal_neighbors. Прежние правила конфликтов по порядку обработчиков остаются.

AABB-запрос использует публичный LevelAccess через внутренний Game::with_level, read-only по отношению к миру/сущностям; фильтр физических триггеров другого мода учитывается. Это дополнительная зависимость от закреплённого GameLevel, не стабильный Host API. Поршни не перемещают этот блок с BE. Опрос/dirty-политика BE требуют профилирования; универсальная совместимость не заявляется. При native_on=false состояние питания очищается следующим серверным тиком; structural source/factory остаются для данных мира. Подробнее DETECTOR.md.

Speedy-разгрузка теперь явно разрешена пользователем и должна сохраняться при дальнейшем переносе. Она использует тот же проверенный whitelist/контракт контейнеров, не новые raw slot-записи.

## Перенаправляющая лента 0.5.0

В обеих частях версия 0.5.0. Новый блок хранит facing и powered в стандартном состоянии. Существующие ID и схемы состояний сохранены. Используются прежние именованные хуки и пины. Для мира, в котором размещены перенаправляющие ленты, используйте подходящую резервную копию при возврате на 0.4.0.

## Сортирующая лента 0.6.0

Обе части 0.6.0 нужны для регистрации нового блока, предмета и меню. Фильтры сохраняются в штатном списке `Items` блока и не доступны воронкам. Для возврата на старую версию используйте копию мира до размещения сортирующей ленты. Пины Horizon и Mixins прежние.

## Выбрасывающая лента 0.7.0

Новый блок наследует facing шаблона бочки и добавляет boolean powered. Настройки хранятся только в его block entity. Для обновления нужны обе части 0.7.0 и пересборка с прежними пинами. Для возврата к 0.6.0 используйте мир до размещения выбрасывающих лент.

## Подъёмники 0.8.0

Два новых ID, `powercraft2:elevator_up` и `powercraft2:elevator_down`, заменяют варианты metadata оригинала. Свойства `powered` и `base` хранятся в состоянии блока. Передача использует прежние правила ванильных контейнеров, теперь также с гранью вверх для контейнера под секцией. Для обновления нужны обе части 0.8.0 и native rebuild с прежними пинами. Для возврата к 0.7.0 используйте копию мира до размещения подъёмников. Игровые проверки движения, коллизии, сохранения и LAN предстоят.

## Разветвитель 0.9.0

Добавлен ID `powercraft2:splitter`. Блок наследует свойства шаблона бочки, фильтры сохраняются в обычном списке `Items`. Доступ к меню проходит через штатные проверки Horizon, автоматические слоты закрыты. Для ожидающего остатка используется attachment `powercraft2:splitter_route` с данными `route_v1`. Нижняя площадка нисходящего подъёмника открывается также над разветвителем. Обе части 0.9.0 требуют native rebuild с прежними пинами. Для возврата к 0.8.0 используйте копию мира до размещения новых блоков.

## Параллельный выпуск 0.10.0

Обе части обновляются вместе с прежними пинами. Контент добавляет декларации мира, поэтому Horizon перечитывает мод после полного перезапуска. Кристаллы появляются в новых чанках. Выполняйте откат 0.9.0 на копии мира, сделанной до добавления блоков и генерации чанков 0.10.0.

Тяга игрока использует клиентскую симуляцию Horizon. Сервер синхронизирует питание блоков штатными обновлениями. LAN и поведение на серверах с другими модами ожидают игрового прогона. Банк опыта проверяет штатное событие изменения XP. Хуки выпадения срабатывают для собственного блока и функции. Публичные идентификаторы Transport из предыдущих выпусков сохранены.
