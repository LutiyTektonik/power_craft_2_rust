# Совместимость

Целевая исходная ревизия Horizon: `9f42064c11efe7ef3e5ed2baad7ddc2a3b36eea0`, Minecraft 26.3. Horizon Mixins: `e59da9094f0c2fdda6c627fe9eff22dec6a906f0`. Официальный cargo check с модом на этой ревизии прошёл. Исходный конвейер подтверждён пользователем в игре; плавность 0.1.1 также подтверждена пользователем. Новые ленты 0.2.0 требуют игровой приёмки.

Обязательных сторонних модов нет. ID мода — `powercraft2`, все новые игровые данные — `powercraft2:*`, единственный добавляемый Rust-модуль — `powercraft2_transport`. В чужие каталоги и пространства имён мод не пишет.

## Использованные точки расширения

| Именованный хук, версия | Действие |
| --- | --- |
| `entity_tick_listened`, 1 | Устанавливает `listened=true`, если мод включён; не сбрасывает ответ других модов |
| `tick`, 1 | Только клиентская копия: предсказание той же скорости после штатной физики |
| `entity_tick_post`, 1 | Только `minecraft:item` над собственным конвейером; меняет скорость через typed API |
| `state_for_placement`, 1 | Только собственные три ленты; выбирает направление, сохраняя уже данный ответ |

Хуки — HEAD без отмены и OVERWRITE. Каталог и blob-идентичность исходников записаны в `API_EVIDENCE.json`. Требуемый уровень хуков 381 покрывает чтение уровня; в выбранном движке имеется 415. Это не обещание поддержки любой ревизии с номером ≥381: добавляемый модуль и сборочный инструментарий привязаны к исходной структуре выбранного commit.

Используются `Host::on/entity/level`, методы `EntityRef::position/velocity/on_ground/set_velocity`, методы `LevelRef::block/block_property/is_loaded`, документированные `GameLevel::native_state_block/native_state_with_property`. Нет ручного редактирования функций движка. Официальный Mixins создаёт отдельное staged-дерево; исходный Horizon не меняется.

## Возможные конфликты

- Несколько native-модов одной сборки должны согласовать ревизии движка и Mixins; полная совместная сборка здесь не выполнена.
- Поле `hooks` в официально упакованном `.hnmod` позволяет Launcher выбрать подходящую другую ревизию Horizon. Для строгого теста указанного commit используйте подготовленный `native-pinned/` без этого необязательного поля и проверяйте оба SHA в `native-mods.json`. Это сохраняет pin Mixins, который теряется при передаче одного внутреннего каталога bundle. См. `WINDOWS11.md`.
- Другой мод, меняющий скорость того же предмета на той же ленте, может переопределить результат. Нет эксклюзивной блокировки физики. Порядок HEAD задаёт Mixins: priority по убыванию, ID мода и ID инъекции по возрастанию; trait-обработчики идут после mixin-инъекций.
- Мод, отменивший Pre тика сущности, предотвращает наш Post. Это поведение сохраняется.
- Мод, претендующий на `powercraft2`, конфликтует по пространству имён. Другие разработчики должны использовать свои идентификаторы.
- Ресурс-пак может заменить нашу графику; это не должно менять игровую механику.
- Нативная часть не меняет размещение чужих блоков. Ориентация своего блока остаётся структурным правилом размещения даже при выключенном движении: `GameLevel` не предоставляет настройку `Host::on` этому адаптеру.

## Мультиплеер и данные

Контентный manifest явно имеет `side="both"`. Клиент и сервер должны иметь одинаковую контентную версию и одинаковое поведение нативной части. Horizon сверяет контентные моды при подключении; по документации native-моды пока не входят в такую сверку. Поэтому одинаковый набор нативных компонентов необходимо обеспечить на уровне сборки.

Движение выполняет авторитетный сервер; клиент получает обычные обновления item entity и с 0.1.1 предсказывает ту же силу ленты на своих копиях предметов. Нет собственного сетевого протокола, копирования стеков или обязательного мода-посредника. Серверная и LAN-проверки с двумя клиентами не проведены.

Единственное новое сохраняемое состояние — блок с `facing`. Не удалять определения этого блока из мира без резервной копии. Совместимость миров 1.7.10 с новым namespace не реализована. Будущие интеграции с инвентарями, энергией и защитой территории оформлять отдельными адаптерами с необязательными зависимостями и документированным поведением.

## Особенность исправления 0.1.1

Публичный setter скорости запрещает клиентские записи. Поэтому клиентский адаптер внутри официального tick-хука читает текущие world/registry и меняет только `Game::dropped` → `ItemEntity::velocity`. Это минимальная зависимость от внутренних полей выбранного commit, необходимая для правильного предсказания; ни position, ни previous, ни счётчики предмета не меняются. Функции движка не переписываются, render hooks и собственные пакеты не добавляются. Проверять эту связь при любом обновлении Horizon. В распространяемом `.hnmod` удалено необязательное поле `hooks`, поэтому его Horizon SHA является строгим pin. Локальный compatibility.json по-прежнему содержит минимальный уровень API 381 для официального инструментария.

## Изменения 0.2.0

Нативная и контентная части — обе **0.2.0**. Добавлены только `powercraft2:speedy_conveyor` и `powercraft2:brake_conveyor`. Старые ID/facing и восемь normal-файлов сохранены; новые блоки используют обычные состояния Horizon. В новой тормозной ленте собственный boolean powered — серверный кэш питания, не redstone-выход. Он перечитывается при обработке предмета, в том числе после загрузки чанка.

Дополнительные публичные helpers: Host::neighbor_signal (API 96) и Host::set_block_property_with (API 33). Уровень 381 менять не требуется. Пишется только собственный brake powered с UPDATE_CLIENTS=2, по изменению значения. Другие свойства/facing и чужие блоки не перезаписываются, соседние обновления не вызываются. Новых хуков и OVERWRITE нет. На пустой ленте cached powered/картинка могут обновиться лишь при следующем предмете; реальное питание на сервере не берётся из кэша.

В 0.2.0 обновить обе части на клиенте/сервере и выполнить native rebuild. Для возврата к 0.1.1 использовать резервную копию мира до установки новых блоков: старый content не знает новые ID. Совместная сборка с другими native-модами и LAN ещё не проверены.
