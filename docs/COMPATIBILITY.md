# Совместимость

Целевая исходная ревизия Horizon: `f4d8d62c31ec2b08046faded7bef1b476783f319`, Minecraft 26.3. Horizon Mixins: `e59da9094f0c2fdda6c627fe9eff22dec6a906f0`. Привязка подтверждает происхождение исходников, **не успешную компиляцию**: игровая проверка ещё не выполнена.

Обязательных сторонних модов нет. ID мода — `powercraft2`, все новые игровые данные — `powercraft2:*`, единственный добавляемый Rust-модуль — `powercraft2_transport`. В чужие каталоги и пространства имён мод не пишет.

## Использованные точки расширения

| Именованный хук, версия | Действие |
| --- | --- |
| `entity_tick_listened`, 1 | Устанавливает `listened=true`, если мод включён; не сбрасывает ответ других модов |
| `entity_tick_post`, 1 | Только `minecraft:item` над собственным конвейером; меняет скорость через typed API |
| `state_for_placement`, 1 | Только собственный блок; выбирает направление, сохраняя уже данный ответ |

Хуки — HEAD без отмены и OVERWRITE. Каталог и blob-идентичность исходников записаны в `API_EVIDENCE.json`. Требуемый уровень хуков 381 покрывает чтение уровня; в выбранном движке имеется 645. Это не обещание поддержки любой ревизии с номером ≥381: добавляемый модуль и сборочный инструментарий привязаны к исходной структуре выбранного commit.

Используются `Host::on/entity/level`, методы `EntityRef::position/velocity/on_ground/set_velocity`, методы `LevelRef::block/block_property/is_loaded`, документированные `GameLevel::native_state_block/native_state_with_property`. Нет ручного редактирования функций движка. Официальный Mixins создаёт отдельное staged-дерево; исходный Horizon не меняется.

## Возможные конфликты

- Несколько native-модов одной сборки должны согласовать ревизии движка и Mixins; полная совместная сборка здесь не выполнена.
- Другой мод, меняющий скорость того же предмета на той же ленте, может переопределить результат. Нет эксклюзивной блокировки физики. Порядок HEAD задаёт Mixins: priority по убыванию, ID мода и ID инъекции по возрастанию; trait-обработчики идут после mixin-инъекций.
- Мод, отменивший Pre тика сущности, предотвращает наш Post. Это поведение сохраняется.
- Мод, претендующий на `powercraft2`, конфликтует по пространству имён. Другие разработчики должны использовать свои идентификаторы.
- Ресурс-пак может заменить нашу графику; это не должно менять игровую механику.
- Нативная часть не меняет размещение чужих блоков. Ориентация своего блока остаётся структурным правилом размещения даже при выключенном движении: `GameLevel` не предоставляет настройку `Host::on` этому адаптеру.

## Мультиплеер и данные

Контентный manifest явно имеет `side="both"`. Клиент и сервер должны иметь одинаковую контентную версию и одинаковое поведение нативной части. Horizon сверяет контентные моды при подключении; по документации native-моды пока не входят в такую сверку. Поэтому одинаковый набор нативных компонентов необходимо обеспечить на уровне сборки.

Движение выполняет авторитетный сервер; клиент получает обычные обновления item entity. Нет собственного сетевого протокола, копирования стеков или обязательного мода-посредника. Серверная и LAN-проверки с двумя клиентами не проведены.

Единственное новое сохраняемое состояние — блок с `facing`. Не удалять определения этого блока из мира без резервной копии. Совместимость миров 1.7.10 с новым namespace не реализована. Будущие интеграции с инвентарями, энергией и защитой территории оформлять отдельными адаптерами с необязательными зависимостями и документированным поведением.
