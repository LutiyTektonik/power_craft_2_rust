# Проверка PowerCraft 2 Horizon на Windows 11

**Статус: экспериментальная проверка исходного прототипа. Готового проверенного игрового релиза и Windows `.exe` нет.** Содержимое `.hnmod` — Rust-исходники, которые Launcher должен собрать. В Cloud Rust и официальная проверка не запускались из-за отсутствия компилятора и недоступной shell-сети. Если нужна только уже подтверждённая рабочая сборка, устанавливать этот прототип пока рано.

## Что находится в тестовом наборе

| Файл/каталог | Назначение |
| --- | --- |
| `packages/powercraft2-0.1.0.hnmod` | Исходный native bundle, созданный настоящим `native/tools/native.py package powercraft2`; не прошёл компиляцию/официальную валидацию |
| `packages/powercraft2-0.1.0-content.hmod` | Контентный ZIP нашего упаковщика; официальный `cargo horizon-mod build/check` заблокирован |
| `native-pinned/` | Распакованный вход Launcher для строгой проверки заданных Horizon и Mixins |
| `VERIFICATION.json` | Фактические результаты команд с отмеченными блокерами |
| `SHA256SUMS.txt` | Контрольные суммы файлов набора; проверка целостности, не цифровая подпись |

Нативная и контентная части нужны одновременно для полного среза. Один `.hmod` может дать только статический контент; он не содержит Rust-движения. Один `.hnmod` не добавляет JSON-описание блока.

## Требования

Windows 11, подходящий по архитектуре Horizon Launcher с поддержкой native mods и Minecraft 26.3 из собственной копии игры. Установите и подготовьте обычную игру через Launcher, проверьте её запуск до добавления прототипа. Создайте отдельный экземпляр **PowerCraft2-Test** и отдельный творческий мир с командами. Нужен интернет для управляемого инструментария и исходников; первая нативная сборка по документации может занимать 20–30 минут и заметное место на диске.

На Windows x64 Launcher использует собственные Rust и MinGW. На ARM64 нужны соответствующие ARM64 Launcher и игра. Не требуется вручную ставить Python, rsync, системный Rust или Visual Studio только ради данного метода. Linux-скрипт `native.py check` не является Windows-инсталлятором. Эти сведения подтверждены исходниками Launcher на pinned commit, а не запуском Windows в Cloud.

## Установка контента через экземпляр Launcher

1. Распакуйте тестовый набор, например в `C:\Games\PowerCraft2-TestKit`.
2. В Launcher выберите отдельный экземпляр **PowerCraft2-Test**. Откройте его игровой каталог через доступное действие открытия папки экземпляра. Используйте именно этот каталог, не общий `.minecraft` другой игры и не папку установки лаунчера.
3. Поместите **один** `powercraft2-0.1.0-content.hmod` в подкаталог `horizon-mods` игрового каталога. При отсутствии создайте его. Нативный `.hnmod` сюда не помещайте.
4. При запуске откройте Options → Mods, включите `PowerCraft 2 Horizon` и полностью перезапустите игру, поскольку мод регистрирует новый блок. Если загрузчик отвергает архив, зафиксируйте точную ошибку; успешная упаковка не гарантирует, что загрузчик примет файл.

## Строгая нативная сборка через Horizon Launcher

Целевые commit:

```text
Horizon: f4d8d62c31ec2b08046faded7bef1b476783f319
Mixins:  e59da9094f0c2fdda6c627fe9eff22dec6a906f0
```

Для этой проверки используйте **`native-pinned/` целиком**, с верхним `horizon-native.json` и вложенным `mixins/`. Запуск только папки `mixins/powercraft2` потеряет pin Mixins; обычный `.hnmod` с `hooks` допускает выбор иной версии движка. В тестовом дескрипторе удалено только необязательное поле `hooks`; остальные metadata и Rust-файлы сохранены.

В PowerShell укажите реальный путь к исполняемому файлу **установленного Launcher**, не к setup-программе. Если имя/путь отличается, возьмите их из ярлыка:

```powershell
$Launcher = 'C:\ПУТЬ-К-ЛАУНЧЕРУ\horizon-launcher.exe'
$Kit = 'C:\Games\PowerCraft2-TestKit'
& $Launcher native-build --help
```

После изучения исходников и собственного решения доверять нативному коду выполните:

```powershell
& $Launcher native-build "$Kit\native-pinned" --instance 'PowerCraft2-Test' --profile dev --trust-native-code
```

Это настоящий CLI Horizon Launcher. Ключ доверия приведён для ручного запуска пользователем: нативный код выполняется с правами его учётной записи. В Cloud эта команда не запускалась. Не добавляйте для строгого теста `--ignore-pins`, `--allow-version-mismatch` или другие моды. Если `native-build` отсутствует, установленный Launcher не поддерживает описанный путь.

Launcher загружает исходники, применяет Mixins, компилирует игру и назначает нативную сборку указанному экземпляру. При успехе выбирайте этот экземпляр в обычном окне Launcher и запускайте его. Проверьте запись **`native-mods.json`** полученной версии: `horizon`, `mixins` должны совпадать с указанными SHA, а набор модов содержать `powercraft2`. Проверка только названия Nightly недостаточна. Командная строка с `native-pinned` передаёт самостоятельный набор исходников; последующие повторные сборки делайте с тем же входным каталогом.

При ошибке сохраните полный вывод и `native/build.log` в каталоге данных Launcher. Если предлагается сборка без проблемного мода, такой результат **не подтверждает PowerCraft**. Не отключайте защиту Windows ради теста: при ошибке запуска компилятора сохраните код отказа для отдельного разбора. В закреплённом Mixins замена уже существующего stage атомарным exchange ограничена Linux; штатный Launcher создаёт свежий output для apply. Не запускайте Linux staging-скрипты проекта вручную на Windows.

## Игровые действия

В новом творческом тестовом мире с командами:

1. **Регистрация/получение.** Выполните `/give @s powercraft2:conveyor 64`. Найдите вкладку «PowerCraft 2: Транспорт», проверьте предмет и русское имя. Установите несколько блоков. Если ID неизвестен — контент не зарегистрирован; это ещё не ошибка физики.
2. **Направления.** Разместите блок, глядя на север, восток, юг и запад. Стрелка должна соответствовать направлению движения. Для независимого от placement теста задайте блок `/setblock 0 65 0 powercraft2:conveyor[facing=east]` и проверьте прочие значения `north/south/west`.
3. **Линия и поворот.** В стороне от построек создайте площадку `/fill 0 64 0 20 64 4 minecraft:stone`, линию `/fill 0 65 0 7 65 0 powercraft2:conveyor[facing=east]`, поворот `/setblock 8 65 0 powercraft2:conveyor[facing=south]` и продолжение `/fill 8 65 1 8 65 4 powercraft2:conveyor[facing=south]`. Бросьте обычный предмет клавишей Q на начало и отойдите, чтобы не подобрать его. Ожидаются движение к востоку и затем к югу. Число предметов в стеке не должно меняться от конвейера.
4. **Селективность.** Бросьте предмет рядом на камень; он не должен получать конвейерное движение. Проверьте проход игрока и моба: данный прототип их не перемещает. Предмет высоко над лентой должен сначала упасть на неё.
5. **Крафт/разрушение.** На верстаке: верхний ряд — три кожи; следующий — слиток железа, красная пыль, слиток железа. Ожидаемый результат — четыре ленты. В тестовом survival проверьте выпадение блока при разрушении.
6. **Тики/FPS.** Сравните движение при разных ограничениях FPS. Используйте `/tick freeze`, затем `/tick unfreeze`: устойчивое продвижение должно следовать тикам. Не требуйте ровно 0,1 блока за тик фактического пути до измерения трения/коллизий.
7. **Чанки/сохранение.** Создайте дополнительную линию через x=16 и отрицательные координаты, запишите количество предметов. Сохраните, выйдите и откройте мир; направление должно сохраниться. Отойдите достаточно далеко для выгрузки и вернитесь. Не ожидайте движения в нетикающем чанке и не ждите бесконечно: обычный despawn предметов не отключён.
8. **Два игрока.** После одиночного теста проверьте LAN с одинаковыми контентом и нативной сборкой у обоих игроков: согласованное положение, движение и одноразовый pickup, без дюпов. Эта проверка ещё не выполнялась.

Для каждого пункта запишите результат, версию Windows/архитектуру, версию Launcher, SHA из build record и приложите лог при ошибке. Только после успешной сборки и этих действий можно утверждать, какие механики работают в игре.

## Получение проверенного релиза

Сейчас доступен только этот тестовый набор. Для релизного статуса нужно восстановить Cloud-сеть, установить закреплённый Rust, выполнить fmt/Clippy/11 Rust-тестов, официальный `native.py check powercraft2`, официальный build/check контента и check native-архива, затем Windows- и игровые тесты. Исходники цели зафиксированы, но подтверждения компиляции ещё нет.
