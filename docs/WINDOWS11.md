# Установка исправления 0.1.1 на Windows 11

Исходный конвейер уже проверен пользователем. Новая версия прошла Rust-тесты, официальную компиляционную проверку настоящего Horizon на Linux и официальный валидатор архивов. **Запуск нового исправления в игре ещё не выполнен.** `.hnmod` содержит Rust-исходники для сборки Launcher, а не готовую Windows DLL.

## Обновление работающего экземпляра

1. Закройте игру. Сохраните копию тестового мира и прежнего native bundle.
2. Оставьте прежний `powercraft2-0.1.0-content.hmod` в `horizon-mods` игрового каталога экземпляра. Его данные не менялись.
3. Замените старый нативный вход на `powercraft2-0.1.1.hnmod`. Не оставляйте две версии `powercraft2` в одном наборе native.
4. Обязательно выполните native rebuild в Horizon Launcher. Простая замена исходного архива без пересборки не обновляет исполняемую игру.

В наборе `packages/` содержит оба архива; `native-pinned/` — распакованное содержимое нового `.hnmod`, готовое для CLI Launcher. `CHANGES.md` объясняет причину и исправление; `VERIFICATION.json` и `logs/` содержат фактические проверки. Контрольные суммы — `SHA256SUMS.txt`.

## Сборка через Launcher

Нужен Windows 11, Horizon Launcher с поддержкой native-build, подготовленный экземпляр Minecraft 26.3 и интернет для инструментария. Launcher управляет собственным Rust/MinGW. При уже работающей установке используйте тот же Launcher. Первая полная сборка может занять значительное время; обновление обычно использует его кэш.

Распакуйте набор, например в `C:\Games\PowerCraft2-TestKit`. Для отдельного теста используйте экземпляр `PowerCraft2-Test`; подставьте своё фактическое имя экземпляра, если обновляете его. Укажите путь к **установленному Launcher**, не setup-файлу:

```powershell
$Launcher = 'C:\ПУТЬ-К-ЛАУНЧЕРУ\horizon-launcher.exe'
$Kit = 'C:\Games\PowerCraft2-TestKit'
& $Launcher native-build --help
& $Launcher native-build "$Kit\native-pinned" --instance 'PowerCraft2-Test' --profile dev --trust-native-code
```

Эта CLI подтверждена исходниками закреплённого Launcher. Ключ доверия передаётся пользователем после собственного решения запускать нативный код. `native-pinned/` передаёт самостоятельный набор: если позже тестируете вместе с другими native-модами, потребуется их согласованный общий вход. Совместная сборка здесь не проверена.

Если получен только `.hnmod`, распакуйте его целиком в пустой каталог `native-pinned` (это ZIP; при необходимости скопируйте с расширением `.zip`). В верхнем каталоге должен быть `horizon-native.json` и подкаталог `mixins`. Передавайте этот верхний каталог, не один внутренний `mixins/powercraft2`.

Новый архив уже имеет строгие пины:

```text
Horizon: 9f42064c11efe7ef3e5ed2baad7ddc2a3b36eea0
Mixins:  e59da9094f0c2fdda6c627fe9eff22dec6a906f0
Native PowerCraft: 0.1.1
Content PowerCraft: 0.1.0
```

Не применять `--ignore-pins` и `--allow-version-mismatch`. В `native-mods.json` готовой версии проверьте `horizon`, `horizon_mixins` и запись мода `powercraft2` версии 0.1.1. Во внутреннем `native/built.json` поле Mixins называется `mixins`. Название Nightly само по себе не подтверждает ревизию. Если Launcher предлагает сборку без проблемного мода, она не является проверкой PowerCraft. При ошибке сохраните полный вывод и `native/build.log`.

После успешной пересборки запустите этот экземпляр. Для новой установки поместите контент в его игровой каталог `horizon-mods`, включите PowerCraft в Options → Mods и полностью перезапустите игру после регистрации блока. Нативный архив в `horizon-mods` класть не требуется.

## Игровая приёмка

1. В отдельном творческом мире с командами получите `/give @s powercraft2:conveyor 64`. Разместите длинную прямую линию и бросьте предмет. Наблюдайте не менее 30 секунд; прежних периодических остановок и скачков быть не должно.
2. Проверьте все четыре направления, поворот линии, центрирование, отрицательные координаты и переход через x/z=16. Направление размещения и данные старых блоков должны сохраниться.
3. Повторите при лимите 30/60/144 FPS и очень низком FPS. При обычной частоте тиков путь за одинаковое число тиков должен совпадать. При перегрузке сервера замедление тиков допустимо; скрывать его телепортацией мод не должен.
4. Бросьте много разных стеков (одинаковые могут слиться), запишите FPS и время тика. Это реальная проверка нагрузки; тесты модели её не заменяют.
5. Выполните `/tick freeze`, затем `/tick unfreeze`. Без игровых тиков лента не должна продолжать физическое движение.
6. Поставьте стену, проверьте остановку; удалите конечную ленту и проверьте падение с края. На обычном соседнем блоке и в воздухе рядом лента не должна приводить предмет в движение. Игроки/мобы сохраняют стандартную физику.
7. Подберите предмет, проверьте количество и отсутствие призрачной копии/повторного подбора. Проверьте слияние, затем сохранение, повторный вход и выгрузку/загрузку чанка.
8. Только после одиночного теста проверьте LAN с двумя клиентами. Native 0.1.1 и content 0.1.0 нужны на обеих сторонах; старый клиент по-прежнему не предсказывает силу ленты.

При сообщении о проблеме приложите ревизии из `native-mods.json`, состояние линии, направление, FPS/время тика и видео. Текущий отчёт — `SMOOTH_MOVEMENT_VERIFICATION.json`; старый `WINDOWS11_VERIFICATION.json` описывает первоначальные ограничения Cloud и не отражает выполненные сейчас проверки.
