# Синхронизация с GitHub

Пользователь указал целевой репозиторий: https://github.com/LutiyTektonik/power_craft_2_rust.git . Локальный origin настроен на него; рабочая ветка — work/transport-detector. Игровая версия остаётся 0.4.0, исходный feature-коммит — c7a850b.

Повторная проверка 2026-11-14: GitHub-коннектор по-прежнему подключён как LutiyTektonik-dev, владелец — LutiyTektonik. Теперь API возвращает pull=true, push=true: право записи аккаунту предоставлено.

Однако реальная запись не прошла двумя способами. `git push -u origin work/transport-detector` с сетевым доступом вернул HTTP 403: Permission denied to LutiyTektonik-dev. Попытка инициализировать README.md в пустом репозитории официальным GitHub-коннектором вернула HTTP 403: Resource not accessible by integration. `git ls-remote origin` успешно выполнился и не вернул refs. Никакие файлы, ветки или теги на GitHub не созданы.

Следует проверить разрешения подключённого приложения GitHub на этот репозиторий: Repository permissions → Contents: Read and write. Для отправки существующего `.github/workflows/check.yml` может также требоваться Workflows: Read and write. Если приложение предлагает обновление разрешений, его должен подтвердить владелец; иначе нужно обновить/переподключить GitHub-интеграцию со штатным правом записи. Членство аккаунта уже исправлено, повторно выдавать ему Write не требуется. Для Git CLI нужна отдельная рабочая авторизация с записью; токены не передавать в чат, секреты не выводить.

После исправления доступа повторно проверить identity/permissions и существующие refs, затем отправить только свою ветку и теги без force push:

```sh
git push -u origin work/transport-detector
git push origin refs/tags/powercraft2-v0.2.0-tested refs/tags/powercraft2-v0.1.1-tested
```

Не заменять main, не применять --mirror/--force и не перезаписывать существующие теги. Если история удалённого репозитория уже существует, сначала исследовать её; подготовить отдельную ветку/PR с сохранением чужих изменений. Для пустого репозитория PR может быть недоступен до появления базовой ветки.

Артефакты/кэши/исходники движка не добавлять в Git. Полная локальная история и теги также сохранены в ранее подготовленном source-and-history ZIP. Этот документ фиксирует подготовку, не успешный push.
