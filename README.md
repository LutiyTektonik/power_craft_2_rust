# PowerCraft 2 Horizon

Восстановление рабочего содержимого PowerCraft 2 (Forge 1.7.10) на Rust/Horizon. **Весь мод ещё не завершён.** Проверенная пользователем база **0.2.0** с обычными, ускоренными и замедленными лентами сохранена тегом `powercraft2-v0.2.0-tested`.

В **0.3.0** добавлена передача выброшенных предметов с обычной и тормозной ленты в соседние vanilla-инвентари. Новая механика прошла Rust/официальные интеграционные проверки, но ещё требует игровой приёмки. Новых игровых объектов или инициативных функций не добавлено. Сохраняются все три ID, плавное движение, рецепты, модели, текстуры и формат состояний — 29 content-файлов побайтно совпадают с базой.

| Лента | Сохранённое движение | Передача в контейнеры 0.3.0 |
| --- | --- | --- |
| powercraft2:conveyor | 0,1 блока/тик | После середины блока: впереди, сбоку, сверху |
| powercraft2:speedy_conveyor | 0,2 блока/тик | Как в опубликованном оригинале, storeNearby не вызывается; закончите быструю линию обычной |
| powercraft2:brake_conveyor | 0,06 блока/тик; redstone гасит скорость | Как у normal; при питании без ожидания середины |

Поддержаны chest/trapped_chest/furnace/hopper/dispenser/dropper/brewing_stand через их настоящие slot/face-правила. Принятые предметы вычитаются из исходного стека, остаток остаётся обычной сущностью. Лимит 64 за тик ограничивает обработку искусственно увеличенных стеков. Клиент не меняет инвентари. [Контракт и ограничения](docs/STORAGE_TRANSFER.md).

## Установка и проверка

Использовать обе части **0.3.0**: `powercraft2-0.3.0-content.hmod` и `powercraft2-0.3.0.hnmod`. Заменить прежние файлы без дубликатов и выполнить native rebuild в Horizon Launcher. `.hnmod` — исходный bundle, Launcher компилирует его в игру; готовой Windows DLL/EXE внутри нет. Начать с копии мира.

[Windows 11: установка и сценарии](docs/WINDOWS11.md). Пины не менялись:

```text
Horizon 9f42064c11efe7ef3e5ed2baad7ddc2a3b36eea0
Mixins  e59da9094f0c2fdda6c627fe9eff22dec6a906f0
Minecraft 26.3
```

```sh
scripts/bootstrap.sh --install
scripts/check.sh
scripts/build.sh
NATIVE_NO_DEFAULT_FEATURES=1 scripts/check.sh --horizon
python3 scripts/prepare-windows.py
```

`source scripts/env.sh` подключает уже установленный в Cloud инструментарий. `scripts/build.sh --source-only` только упаковывает, не подтверждая сборку игры. Реально прошли **37 Rust- и 25 Python-тестов**, форматирование/Clippy, официальный cargo check настоящего Horizon с модом, content build и валидатор обоих архивов. Игровой запуск 0.3.0, LAN и реальные FPS/TPS пока не проверены. [Точный отчёт](docs/VERIFICATION.json), [приёмка](docs/TESTING.md).

## Соответствие оригиналу

Сверены 26 опубликованных JAR/source-JAR 0.1.0B: 427 Java-файлов, 404 совпадают с GitHub побайтно, 23 отличаются. Публикация, исходник и прохождение внутри игры — разные уровни доказательства. Экспериментальные Logic/Storage/Mobile, неисправные и незавершённые подфункции сейчас **отложены**. Их не исправляем попутно и не выдаём за рабочее содержимое оригинала.

Принятые отличия 0.2.0 — высота 1/4, ограниченные скорости/клиентское предсказание, стандартный pickup/despawn Horizon и прежние medium-рецепты — сохраняются. Они отдельно отмечены; beta-рецепты не заменяют уже существующие определения.
