# PowerCraft 2 Horizon

Поэтапный перенос PowerCraft 2 с Forge 1.7.10 на Rust/Horizon. **Весь мод ещё не перенесён.** В выпуске **0.2.0** развита основа Transport: к обычному конвейеру добавлены быстрая и тормозная ленты. Новые ленты прошли Rust-проверки и официальную проверку интеграции с закреплённым Horizon; игровая приёмка 0.2.0 ещё требуется.

Пользователь подтвердил размещение и плавное перемещение предметов на обычной ленте **0.1.1**. Эта база сохранена тегом `powercraft2-v0.1.1-tested`. Старый ID `powercraft2:conveyor`, его facing, форма, рецепт и ресурсы не менялись; тест проверяет побайтную сохранность восьми файлов. [Проверенная база](docs/BASELINE.md).

| Блок | Поведение |
| --- | --- |
| `powercraft2:conveyor` | Прежняя лента: 0,1 блока/игровой тик, четыре направления |
| `powercraft2:speedy_conveyor` | Быстрая лента: 0,2 блока/тик; голубая стрелка |
| `powercraft2:brake_conveyor` | Без питания 0,06 блока/тик; при redstone тяга отключается, горизонтальная скорость гасится ×0,6 после обычной физики |

Это целевые скорости свободной ленты; стены/коллизии и реальная частота тиков влияют на путь. Передача предметов в сундуки, особая упаковка, детектор, сортировщик, подъёмники и остальные Transport-механизмы пока не реализованы. Стандартные гравитация, коллизии, слияние, подбор и сохранение остаются в Horizon. Лента воздействует только на выброшенные предметы.

## Установка 0.2.0

Использовать **обе части 0.2.0**: `powercraft2-0.2.0-content.hmod` и `powercraft2-0.2.0.hnmod`. Контент нужно заменить, native — заменить и пересобрать в Launcher. В отличие от hotfix 0.1.1, этот выпуск добавляет новые определения блоков. Не оставлять две версии одного ID в одном экземпляре. Начать с копии тестового мира.

[Инструкция Windows 11](docs/WINDOWS11.md) содержит команду Launcher, получение блоков и приёмочные сценарии. `.hnmod` содержит Rust-исходники для сборки Launcher, не готовую DLL/EXE. Распространяемый архив строго закрепляет ваши Horizon/Mixins:

```text
Horizon 9f42064c11efe7ef3e5ed2baad7ddc2a3b36eea0
Mixins  e59da9094f0c2fdda6c627fe9eff22dec6a906f0
Minecraft 26.3
```

## Проверки и сборка

```sh
scripts/bootstrap.sh --install
scripts/check.sh
scripts/build.sh                 # Rust-библиотека, официальная упаковка/проверка архивов
NATIVE_NO_DEFAULT_FEATURES=1 scripts/check.sh --horizon
python3 scripts/prepare-windows.py
```

Для облегчённой упаковки без проверки движка: `scripts/build.sh --source-only`. Полная интеграция скачивает источники по SHA; кэши и сторонние файлы не входят в Git. Cloud уже имеет инструменты в `.tools`; `source scripts/env.sh` подключает их.

Реально прошли **25 Rust-тестов**, **22 Python-теста**, форматирование, Clippy с `-D warnings`, официальный `native.py check` настоящего Horizon и `cargo horizon-mod check` обоих архивов. Модели разных FPS/партий предметов не являются игровым benchmark. [Текущий отчёт](docs/VERIFICATION.json), [проверки и ограничения](docs/TESTING.md).

## Объём переноса

Изучено полное исходное дерево: 427 Java-файлов, 62 декларации объектов (включая служебные), 177 деклараций рецептов разных режимов, 78 GUI/container/виджет-классов. Это статическая инвентаризация, не подтверждение исправности оригинального Forge-мода. Logic/Storage/Mobile и отдельные TODO учитываются как незавершённые исходные функции; отсутствующие Weasel, CheckPoints, общая энергетика и Integrations отделены от существующего функционала.

- [Архитектура](docs/ARCHITECTURE.md), [совместимость](docs/COMPATIBILITY.md), [лицензии](docs/LEGAL.md)

Одна небольшая Cargo-библиотека содержит чистую транспортную механику; тот же файл подключается через официальный Mixins. Маленькие адаптеры разделяют серверную логику, клиентское предсказание и размещение. Пустые будущие модули не созданы. Проект не связан официально с Mojang/Microsoft/авторами PowerCraft.
